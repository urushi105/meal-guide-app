# 音声案内食事支援アプリ（PWA）

食卓を撮影して YOLOv8n で料理と手を検出し、**どこに何があるか**を音声（VoiceOver）で案内する Web アプリです。

---

## できること

| 機能 | 内容 |
|---|---|
| ジェスチャー | 開始（`gesture_start`）＝**3秒見せ続けると**案内開始 ／ 再検出（`gesture_redetect`）＝**見せるとすぐ**再検出（開始から終了まで何回でも） ／ 終了（`gesture_end`）＝**3秒見せ続けると**案内終了 |
| 初期案内 | 案内開始・再検出のとき、食卓を約4秒ながめて、(1) 熱い物（味噌汁・ご飯）、(2) 食べてはいけない物（箸）の順に「何時の方向か」を案内。**お盆が見つかれば、お盆の中心を基準**にします |
| 手動ボタン | 画面下の「音声案内開始」「音声案内終了」 |
| 文字起こし | 音声で出力する内容を、画面中央に白い文字で表示 |
| 詳細設定 | 左上の丸いボタンから。モデル名・文字の大きさ(S/M/L)・再生速度(0.1〜2.0)・カメラ倍率(0.5〜1.0)・データ保存 |

---

```

│   ├─ gesture.js      指数字ジェスチャーの判定
│   ├─ guide.js        初期案内づくり（食卓スキャン・時計方向）
│   ├─ speech.js       音声（VoiceOver）で読み上げる
│   ├─ camera.js       カメラと倍率
```

## 使い始める手順

### 手順1：クラス名を確認する

学習したモデルのクラス名（食事データ＋指数字データ）を確認します。

```
python tools/export_model.py "last.pt の場所\last.pt"
```

> `last.pt` はふつう、学習した結果のフォルダ `runs\detect\train○\weights\last.pt` にあります。
> 場所を指定しないと、いまのフォルダの `last.pt` を探します（無いとエラーになります）。

画面に `0: ○○` `1: △△` …と表示されます。

### 手順2：last.pt を ONNX に変換して置く

手順1のコマンドで `last.onnx` ができます。これを **`model/last.onnx`** に置きます。

### 手順3：クラス名の対応表を合わせる

`js/config.js` の中を、自分のクラス名に合わせます。

- **`CLASS_TABLE`** … 料理などの名前。`words` に、クラス名に含まれる文字を書きます（英語でも日本語でも可）。`hot: true` が「熱い物」、`inedible: true` が「食べてはいけない物」です（どちらも案内開始時に方向を案内します）。
- **`GESTURE_BY_CLASS_NAME`** … ジェスチャーのクラス名（`gesture_start` など）と動作の対応です。

### お盆のクラスを追加すると、方向が正確になります

方向（何時の方向）は、**お盆の中心**から各料理の中心への向きで決めます。お盆のクラスが無いモデルでは、カメラ画像の中心が基準になるため、お盆が画像の中心からずれると方向もずれます。

1. 画像にお盆のクラス（例：`obon`）を追加してアノテーションする
   - **お盆が写っている画像は、すべてにお盆のラベルを付けてください**（一部だけだと、ラベルの無いお盆が「背景」として学習され、精度が下がります）
   - 既存のラベルの番号を変えないよう、`data.yaml` の **いちばん最後（12番）に追加**します
2. 統合データセットで学習し直し、`last.onnx` を作り直して置き換える
3. アプリは、クラス名に `obon` / `tray` / `お盆` / `トレー` が含まれていれば、自動でお盆を使います（違う名前なら `config.js` の `CLASS_TABLE` の `words` に足します）

お盆が見つかったときは「お盆の中心から見た方向でお伝えします」と最初に案内します。お盆のクラスはあるのに今回は見つからなかったときは、「お盆が見つかりませんでした。画面の中心から見た方向でお伝えします」と案内して、画像の中心で代用します。基準点にとても近い物は「お盆の中央」と案内します（範囲は `SCAN.CENTER_ZONE_RATIO`）。
- **指数字のクラス名** … `1` `one` `finger1` `指1` などは自動で認識されます。違う名前のときは `config.js` の `PREFIXES` / `NUMBER_WORDS` に足してください。

> 対応表にないクラスが見つかると、ブラウザの開発者ツール（コンソール）に
> 「対応表にありません」と表示されます。画面の検出枠にも名前が出るので、確認に使えます。

### 手順4：動かす

**パソコンで試す**

アプリのフォルダ（`index.html` があるフォルダ）で、次を実行します。

```
python -m http.server 8000
```

> Windows は `python`、Mac / Linux は `python3` と入力します。

ブラウザ（Chrome か Edge）で `http://localhost:8000` を開きます。止めるときはターミナルで `Ctrl + C` です。

> パソコンでは VoiceOver が使えないため、音を出して試すときは `js/config.js` の
> `SPEECH.MODE` を `"synthesis"` にしてください（iPhone で使うときは `"voiceover"` に戻します）。

**iPhone で使う**

iPhone のカメラは **HTTPS のページでしか使えません**。次のどちらかで公開してください。

- GitHub Pages・Netlify・Cloudflare Pages などに `meal-guide-pwa` フォルダの中身をアップロードする（無料）
- 研究室で動画収集アプリ（PWA）を公開している場所と同じ方法で公開する

公開したら、iPhone の Safari で開き、**共有ボタン →「ホーム画面に追加」**。ホーム画面のアイコンからアプリとして起動できます。

### 手順5：VoiceOver をオンにする

音声は VoiceOver が読み上げます。

- iPhone の「設定」→「アクセシビリティ」→「VoiceOver」をオン
- ショートカットにしておくと便利：「設定」→「アクセシビリティ」→「アクセシビリティショートカット」→ VoiceOver（サイドボタンの3回押しで切り替え）

## 使い方

1. アプリを開くと「モデルを読み込んでいます」→「準備ができました」と案内される
2. スマホをスタンドなどで固定し、**食卓全体が映る**ようにする（画像の上が食卓の奥になる向きが標準）
3. **開始のジェスチャーを見せ続ける** → 「3秒後に案内を開始します」→ 3秒後に開始
   （途中で手を下ろす・1秒以上見えなくなるとキャンセル）
4. 開始すると「手を下ろしてください」と案内され、約4秒で食卓をスキャンして、初期案内が流れる
   例）「熱い物があります。味噌汁は3時の方向、ご飯は9時の方向です。」「食べてはいけない物があります。箸は6時の方向です。」
5. 料理を動かしたときなどは **再検出のジェスチャー** → すぐスキャンをやり直して初期案内をもう一度（開始から終了まで何回でも使えます）
7. 終わるときは **指3本** → 「案内を終了します」

> 一度実行したジェスチャーは、**いったん手を下ろしてから**でないと次を受け付けません（手を上げっぱなしで何度も実行されるのを防ぐため）。

### 「データを保存する」

アプリを開いてからの記録（読み上げた文章・ジェスチャー・検出結果）を CSV にして保存します。iPhone では共有シートが開くので「ファイルに保存」を選びます。検出結果は1コマごとに「クラス名:自信度@中心x,y」と処理時間(ms)が入っているので、検出精度の評価に使えます。

## 調整したいとき（js/config.js）

| 困りごと | 変える場所 |
|---|---|
| ジェスチャーが実行されるまでの時間を変えたい | `GESTURE.HOLD_MS`（動作ごと。`start` / `end` = 3000、`redetect` = 0 ですぐ実行。再検出も3秒にしたいときは 3000） |
| ジェスチャーの誤作動が多い | `GESTURE.CONF_THRESHOLD` を上げる / `START_FRAMES` を増やす |
| 再検出が意図せず動いてしまう | `GESTURE.START_FRAMES` を増やす / `HOLD_MS.redetect` を 1000 などにする |
| 「そのほかの料理」も案内したい | `SCAN.ANNOUNCE_OTHERS = true` |
| 「何時の方向」がずれる | お盆のクラスを追加して学習し直す（上の説明）。お盆が使えないときは、スマホの置き方を調整するか `SCAN.CENTER_MODE = "dishes"`。向かい側に置くときは `SCAN.ROTATE_180 = true` |
| 「お盆の中央」と言われすぎる／言われない | `SCAN.CENTER_ZONE_RATIO`（0.12 = お盆の短い辺の12%以内） |
| 案内が途中で途切れる | `SPEECH.VOICEOVER_MS_PER_CHAR` を大きくする |
| 熱くなる・電池が減る | `MODEL.MIN_INTERVAL_MS` を大きくする |
| 動作が重い | モデルを `imgsz=416` や `320` で変換し直す（精度は下がります） |
| 方向の言葉を変えたい | `DIRECTION_WORDS`（奥／右奥／右 … ） |
| 熱い物・食べてはいけない物の対象を変えたい | `CLASS_TABLE` の `hot` / `inedible` |

### 再生速度について

VoiceOver が読み上げる場合、**読み上げの速さは iPhone 本体の設定**（「設定」→「アクセシビリティ」→「VoiceOver」→「読み上げ速度」）で決まり、アプリからは変えられません。そのため詳細設定の「再生速度」は、`config.js` の `SPEECH.MODE` を `"synthesis"`（ブラウザの音声合成）にしたときに使われます。`"synthesis"` なら VoiceOver がオフでも音が出ます。

### カメラ倍率について

倍率の変え方は端末によって違うため、次の順で試します。

1. カメラのズーム機能（対応端末のみ）
2. 超広角レンズ ⇔ 通常レンズの切り替え（0.7以下で超広角）
3. どちらもできなければ変更不可（設定画面に表示されます）

## 動作確認でわかっていること／まだわかっていないこと

**確認できていること**（パソコン上の Chromium＋疑似カメラで検証）
- 本物の YOLOv8n（ONNX）の読み込み・推論・クラス名の自動取得・検出枠の表示
- 開始／終了のジェスチャー（3秒保持・キャンセル）、再検出のジェスチャー（すぐ実行・手を下ろすまで再実行しない・何回でも使える）
- 初期案内の文章（熱い物 → 食べてはいけない物）、お盆を基準にした方向（お盆あり／写っていない／クラス自体が無い、の3通り）、手動ボタン、設定の保存、CSV保存
- カメラ倍率のレンズ切り替え（カメラ名を模擬して検証）
- モデルが無い・クラス数が合わないときのエラー案内

**まだ確認できていないこと**（実機での確認をお願いします）
- 学習済みの `last.pt`（食事＋指数字）での検出精度・ジェスチャーのクラス名
- iPhone 上での処理速度、発熱、VoiceOver による実際の読み上げと間隔
- iPhone でのカメラ倍率（ズーム機能の対応状況は iOS のバージョンによります）

## うまく動かないとき

| 症状 | 確認すること |
|---|---|
| 「モデルを読み込めません」 | `model/last.onnx` があるか。名前は合っているか |
| 「クラス数が合いません」 | `config.js` の `FALLBACK_CLASS_NAMES` を、学習時の names と同じ順に直す |
| 「カメラを使用できません」 | HTTPS で開いているか。ブラウザのカメラ許可がオンか |
| 音が出ない | VoiceOver がオンか。または `SPEECH.MODE = "synthesis"` を試す |
| 指数字が反応しない | 検出枠のラベルを確認。クラス名が違うなら手順3 |
| 更新したのに古いまま | `service-worker.js` の `CACHE_NAME` の数字を変えて公開し直す |
| iPhone で動作が遅い | `MODEL.MIN_INTERVAL_MS` を大きくする／モデルを小さい画像サイズで変換し直す |
